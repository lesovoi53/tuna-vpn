# Участие в разработке

Сначала откройте issue с задачей, ожидаемым поведением и ограничениями. Для безопасности используйте [SECURITY.md](SECURITY.md), а не публичный дамп.

1. Клонируйте репозиторий с подмодулями и создайте отдельную ветку.
2. Прочитайте [архитектуру](docs/development/architecture.md) и нужный раздел [разработки](docs/development/README.md).
3. Воспроизведите дефект синтетическим тестом. Не используйте рабочие подписки и ключи.
4. Сохраните совместимость существующих профилей и обновления APK. Новые форматы должны иметь валидацию, миграцию и round-trip тест.
5. Выполните относящиеся к изменению проверки; приложите команды и результаты. Для native-патчей обновите provenance и протестируйте соответствующее ядро.
6. PR должен описывать поведение до/после, риск, проверки, непроверенные сценарии и происхождение заимствованного кода.

Не объединяйте обновление всех зависимостей с исправлением одного бага. Не включайте auto-merge/публикацию релиза без решения сопровождающего. Код сторонних проектов принимается только с совместимой лицензией и сохранёнными уведомлениями. CLA не требуется; вклад предоставляется на условиях соответствующего компонента.
