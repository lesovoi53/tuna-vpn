# Issue #3: конфигурации в памяти

Кандидат **1.6.1-rc1**, Android versionCode **26101809**, 18 октября 2026.
Изменения включены в выпуск **1.65**, versionCode **26102008**. Ниже сохранена
история проверок кандидатов; результат финального APK указан в `validation.json`
выпуска. Закрытие issue относится к перечисленным дефектам, а не к защите от root.

## Что изменено

- В Manifest установлено `usesCleartextTraffic=false`, а в
  `network_security_config.xml` — `cleartextTrafficPermitted=false`.
  Исключений для localhost/LAN и пользовательских CA нет.

- URL загрузки конфигураций, подписок и связанных управляющих ресурсов требуют
  HTTPS. Исключения для LAN/локальных адресов удалены; проверяется каждый
  переход перенаправления, включая попытку перехода с HTTPS на HTTP.
- Строковые настройки DataStore уже защищены AES-256-GCM с ключом Android
  Keystore и атомарной миграцией. Эта защита появилась ранее и сама по себе
  не защищала временные конфиги, передаваемые ядрам.
- Нативный launcher получает снимок конфигурации через stdin, размещает его
  в анонимных файлах памяти (`memfd`) и передаёт ядру собственные дескрипторы
  `/proc/self/fd/N`. Секреты не нужны в argv или именах файлов на диске.
  Каждый новый процесс получает собственный снимок; перезапуск не использует
  устаревшие номера дескрипторов. Ошибка создания/подготовки файла памяти
  прекращает запуск: записи plaintext-конфига на диск как запасного пути нет.
- Для HEV, работающего внутри процесса приложения, JNI создаёт файл памяти,
  а сервис удерживает его дескриптор до завершения нативного потока. Замена
  конфигурации сохраняет порядок остановки потока и освобождения дескриптора.
- Mieru валидирует конфигурацию один раз и хранит protobuf-снимок в памяти.
  Повторные чтения получают копии; вторичный файл `native.json` не создаётся.
- Xray принимает JSON-массив приватных аргументов через `-args-config`.
  Ошибки разбора этого массива не печатают значения аргументов.
- qWDTT читает VK-хеши и пароли из дескриптора `-config`, сохраняя stdin для
  CAPTCHA, TURN credentials и команд управления. Содержимое stdin больше
  не выводится в лог. В SOCKS-режиме приложения полученный WireGuard-конфиг
  не печатается и не сохраняется в `wg-turn.conf`.

Изменения уменьшают раскрытие секретов через остаточные runtime-файлы,
командную строку процессов, диагностическое эхо и HTTP-передачу управляющих
данных. Они не меняют автоматически транспорт пользовательского VPN-профиля
и не означают, что весь сетевой трафик приложения становится HTTPS.

## Границы

Работающему ядру нужны расшифрованные секреты. Root, скомпрометированный процесс
приложения или средства с доступом к его памяти остаются за пределами этой
защиты. Файлы памяти не являются шифрованием оперативной памяти.

Явно запрошенный пользователем экспорт профилей/конфигураций может содержать
секреты. Файлы браузерного отпечатка qWDTT (`vk_profile.json`,
`captcha_browser_fp`) также остаются: это идентичность браузера/устройства,
а не пароли туннеля или ключи WireGuard. Старое поведение экспорта qWDTT
вне используемого приложением SOCKS-режима не изменено.

Целевая платформа — Android API 26+. Если старое или изменённое ядро устройства
не поддерживает требуемый механизм анонимных файлов, подключение завершится
ошибкой; небезопасного дискового fallback нет. Совместимость таких устройств
этим кандидатом пока не подтверждена.

## Проверки кандидата

Подтверждены **26 host-тестов memory runtime** и **18 тестов HTTPS-политики**.
Пересобраны Xray, Mieru и qWDTT; их целевые Go-тесты и проверки соответствия
исходников/бинарников provenance прошли. Это не заменяет запуск на Android.

Для build `26101809` прошли сборка release, lint, 898 JVM-тестов без ошибок и пропусков. На Android прошли DNS (4/4) и HTTPS (256 КиБ) через семь доступных профилей: VLESS, два Snell, Mieru, Naive, qWDTT и MasterDNS при MTU 1280.

Отдельная memfd-проверка подтвердила повторное чтение через JNI, затем завершилась ошибкой во время сканирования. Старый отчёт не содержит достаточной диагностики для определения причины; проверку отсутствия секретов на диске **нельзя считать пройденной**. В rc2 сканер сохраняет безопасную причину отказа и частичные счётчики, имеет пределы 1 ГиБ / 120 секунд и не считает неполный обход успешным. 12 синтетических host-проверок сканера прошли. Повтор на устройстве 20 октября с установленным rc1 завершился успешно: 145 файлов, 316323966 байт, 0 совпадений синтетического секрета, 0 запрещённых runtime-файлов; повторное чтение, закрытие и повторный close прошли. VPN был выключен до и после проверки. Это проверка synthetic canary и известных имён файлов, а не универсальный аудит всех возможных секретов в памяти/на диске.

Повторная проверка rc2 на устройстве также завершилась успешно:
148 файлов, полный обход в пределах лимитов, 0 совпадений synthetic canary,
0 запрещённых runtime-файлов, повторное чтение и повторное закрытие дескриптора
успешны; VPN выключен до и после. Эти результаты не заменяют повтор на
окончательном APK; его статус указан в `validation.json` релиза.

Финальная 1.65 (`26102008`) прошла повтор на устройстве после установки обновлением:
157 файлов, 317322872 байта, полный обход, 0 synthetic-canary совпадений,
0 запрещённых runtime-файлов. Повторное чтение, закрытие и повторный close успешны;
VPN выключен до и после, вспомогательный package удалён. SHA-256 установленного
APK совпал с публикуемым. Это целевая проверка перечисленных механизмов,
не универсальное доказательство отсутствия любых секретов на диске.
