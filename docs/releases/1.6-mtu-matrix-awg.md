## Исправление импорта

На физическом планшете с 26101807 воспроизведено: импорт `.conf` успешно
сохраняет отдельный AWG-профиль, но возвращает экран в раздел подписок.
Переключение в «Мои серверы» показывает сохранённую запись. Это ошибка
навигации, а не неподдерживаемые параметры присланного конфига.

В 26101808 файловый импорт передаёт окончательный локальный ID первого
успешно сохранённого профиля в существующий механизм показа профиля.
Он выбирает нужный раздел, очищает мешающие фильтры и раскрывает группу.
Это работает также для нескольких файлов и ZIP; частичная ошибка не теряет
цель перехода. Существующий профиль подписки не заменяется локальной копией.

Обезличенная регрессионная конфигурация сохраняет все расширенные поля:
S1–S4, H1–H4, I1–I5, HeaderProtectionKey, диапазоны таймеров,
ContentPaddingAddition, RandomTrailers и DisableCookies. Проверены `.conf`,
текстовый импорт, редактор, сериализация, сосуществование подписки и локальной
копии. Host-проверка сгенерированного native JSON завершилась успешно.
Настоящие ключи и адреса в тестовую fixture не включены.

На физическом планшете 26101808 повторён файловый импорт присланного
пользователем конфига из раздела подписок: после выбора `.conf` новая
локальная запись автоматически появилась на экране. Временные исходные
файлы с ключами удалены с компьютера и из Downloads устройства.

## Метод проверки MTU

Физический планшет Android API 36, отдельное probe-приложение с другим UID
и сертификатом. Для каждой точки: отключение VPN, сохранение MTU через UI,
подключение выбранного профиля, подтверждение реального MTU через
LinkProperties, четыре DNS-запроса, HTTPS GET 262144 байт с обычной проверкой
TLS, HTTP 200 и стабильной VPN-сетью. Процесс probe не привязан к иной сети.

Точки: 1280, 1500, 9000, 32768 и 65535. Матрица основных профилей выполняется

## Пропущенный JVM-тест

Исторический результат при сборке APK описан ниже. Последующая доработка
тестов заменила пропуск обязательным встроенным синтетическим набором:
`AdvancedProtocolFixtureTest.bundledAndOptionalPrivateFixtures`.
Частные `.uri` по-прежнему подключаются дополнительно через переменную среды;
отсутствие переменной больше не пропускает тест. Код приложения/APK не менялся.
Повторный штатный JVM-прогон после этой доработки: **892 теста, 0 ошибок,
0 пропусков**. Встроенные Snell v6, TUIC, AnyTLS и расширенный AWG прошли
разбор, проверку валидности и генерацию outbounds/endpoints с маршрутом VPN.
Это не означает, что дополнительные частные `.uri` или реальные серверы
были проверены данным JVM-прогоном.

`AdvancedProtocolFixtureTest.privateAdvancedFixtures` требует переменную
`TUNA_ADVANCED_FIXTURES` с каталогом частных `.uri` fixtures. Без неё
срабатывает `assumeTrue` и тест пропускается. Он проверяет разбор и генерацию
конфигурации; это не проверка подключения. MTU/Mieru/AWG-регрессии не пропущены.

## Границы

Передача 256 КиБ по HTTPS не означает передачу IP-пакетов по 65535 байт.
Это функциональная проверка DNS/TCP, не замер максимальных UDP-датаграмм,
скорости, длительной нагрузки, сна или смены физической сети. Максимальный
MTU не является рекомендацией для каждого сервера. Протокольные значения
MTU WireGuard/AWG не подменяются глобальным MTU Android TUN.

Без рабочих профилей не выполнялась сетевая проверка Hysteria2, Trojan,
Shadowsocks, TUIC, AnyTLS, WireGuard, TrustTunnel и WebDAV.
