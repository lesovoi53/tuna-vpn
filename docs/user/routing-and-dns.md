# Маршрутизация и DNS

Маршрутизация выбирает действие для трафика: через VPN, напрямую или блокировать. DNS преобразует домены в IP-адреса и имеет собственные маршруты. Согласуйте обе части, чтобы сайт и его DNS обслуживались ожидаемым способом.

## Правила сайтов и адресов

В редакторе задайте правила и маршрут по умолчанию для трафика, который не совпал с ними. Порядок правил и приоритет групп имеют значение при пересечении условий.

| Условие | Назначение |
| --- | --- |
| `domain:example.com` | Домен и его поддомены |
| `full:example.com` | Точное имя домена |
| `keyword:example` | Совпадение по фрагменту имени |
| `regexp:` | Регулярное выражение поддерживаемого переносимого подмножества |
| `geosite:` | Категория доменов из выбранной базы |
| IPv4, IPv6 или CIDR | Адрес или сеть |
| `geoip:` | Категория IP из выбранной базы |

Не вставляйте полный URL с путём в поле доменного правила. Для GEO-условий нужны совместимые загруженные базы GeoIP/GeoSite. Названия категорий зависят от источника базы. Ошибка загрузки или отсутствующая категория требует исправления; текст правила сам по себе не обеспечивает наличие базы.

## Приложения

В исключениях приложений выберите один из режимов: выбранные приложения работают без VPN (`bypass`) либо только выбранные приложения работают через VPN (`vpn`). Проверьте включение фильтрации. Системные приложения могут быть скрыты фильтром списка.

Список использует Android package name, а не отображаемое название. Отсутствующее на устройстве приложение не получает маршрут только потому, что его пакет присутствует в импортированной ссылке. Исключённый из VPN процесс выходит напрямую и не проходит обычную обработку правил внутри туннеля.

Старый формат импорта имеет вид `tuna://app-exclusions/v1?mode=bypass&packages=com.example.client`. Он включает фильтрацию, выбирает режим и дополняет соответствующий список. После применения переподключите VPN.

## DNS

Предусмотрены независимые группы DNS: напрямую и через VPN. Каждая содержит от одного до восьми серверов. В режиме «Авто» клиент выбирает сервер с учётом доступности; «Приоритет» использует порядок списка. Резервирование остаётся внутри своей группы. Это свойство настройки DNS не является общей гарантией отсутствия утечек всего устройства.

Для текущего общего пути маршрутизации Android выбирайте UDP, TCP или DoH: он использует Xray, где DoT отклоняется проверкой конфигурации. Формат DNS и редактор Builder также содержат DoT для extended-маршрутизатора, но наличие такого поля не означает доступность DoT в текущем пользовательском пути Android.

- UDP/TCP: IP-адрес, при необходимости с портом.
- DoH: HTTPS-адрес резолвера, например `https://dns.example.com/dns-query`. Это синтетический адрес, замените его рабочим.
- DoT: `tls://dns.example.com:853` без пути. Для доменного имени требуется Bootstrap IP.

Bootstrap IP помогает разрешить адрес самого DNS-сервера. Для DoH он необязателен; для DoT с доменным именем обязателен. Hosts задаёт локальные соответствия имён и IP. Запись hosts не должна противоречить Bootstrap IP того же имени.

Общий тайм-аут DNS настраивается от 1000 до 10000 мс, исходное значение — 5000 мс. Стратегии A/AAAA: `UseIP`, `UseIPv4`, `UseIPv6`; также есть управление кэшем. Выбор только IPv6 требует работоспособного IPv6-маршрута.

Полный перенос правил, DNS и приложений доступен через [Routing Builder](../routing-builder.md). Правила подписки могут применяться автоматически: сначала ознакомьтесь с [поведением подписок](subscriptions.md).
